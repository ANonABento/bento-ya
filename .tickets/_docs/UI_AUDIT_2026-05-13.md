## Punch list

### P0 — broken

None found. The app renders and reacts correctly on every surface
exercised. Console-log scrape returned 0 errors (note: WebKitGTK doesn't
implement `browser.getLogs('browser')`, so this is best-effort).

### P1 — confusing / accessibility hazards

#### P1-1. Settings panel has no Escape-to-close handler
The panel only closes via the dedicated × button. Every other modal in the
app (column config, delete confirmations, command palette) closes on
Escape — this inconsistency was already noted in `screenshots.spec.mjs`.

- **Evidence:** test 16 — opened settings, sent Escape, panel stayed open
  (`settings.escape: stillOpen=true`). Confirmed by code:
  `src/components/settings/settings-panel.tsx` has zero `Escape` references.
- **Fix:** mirror the `useEffect` keydown listener pattern from
  `src/components/kanban/column-config-dialog.tsx:149-156`.
- **Screenshot:** `06-settings-workspace.png`

#### P1-2. Icon-only header buttons missing aria-label
Three top-right tab-bar buttons and the budget pill are icon-only with a
Tooltip but no `aria-label` — screen readers and accessibility scanners
will announce them as anonymous buttons.

- **Evidence:** ariaIssues board scan found three unlabeled `<button>`s at
  y=4 (x=1239, 1271, 1302) and one at y=866 x=1409. Source:
  `src/components/layout/tab-bar.tsx`:
  - `AddTabButton` (line 131) — has Tooltip "New Workspace", no aria-label
  - `ShowArchivedButton` (line 191) — has Tooltip "Show/Hide archived", no aria-label
  - `ChecklistButton` (line 218) — has Tooltip "Checklist", no aria-label
  - Budget indicator (`$<0.01` pill) — also unlabeled
  - `SettingsButton` (line 160) is the only one with `aria-label`.
- **Fix:** add `aria-label` matching the Tooltip content for each.
- **Screenshot:** `01-board.png` (top right corner)

#### P1-3. Color-picker swatches in column config are unlabeled
The "Color" group in Configure Column → General is 11 circular buttons
with class `h-6 w-6 rounded-full` and no name. The active swatch only
differs visually by `scale-110 ring-2 ring-white/50`.

- **Evidence:** column-config ariaIssues scan flagged 11 unlabeled buttons
  in a row at y=377/405.
- **Fix:** add `aria-label="Color: orange"` etc. plus
  `aria-pressed={active}` (so the active swatch is announced).
- **Screenshot:** `17-column-config-general.png`

#### P1-4. Toggle switches lack a11y semantics
The pill-shaped toggles across multiple settings tabs (Workspace —
Persistent agent sessions; Voice — Push-to-talk; GitHub — Enable Sync;
Board — every PR badge toggle; column config — Auto Advance) are
`<button>` elements with class `relative inline-flex … rounded-full
transition` and no `aria-label`, no `role="switch"`, no `aria-checked`.

- **Evidence:** settings ariaIssues scan flagged one such toggle at
  (1381, 779); the Board tab (`08-settings-board.png`) shows ~10 more.
- **Fix:** wrap the switch primitive (likely shared in
  `src/components/shared/`) with `role="switch"` + `aria-checked={value}`
  + an `aria-label` derived from the adjacent label.
- **Screenshots:** `06-settings-workspace.png`, `08-settings-board.png`,
  `10-settings-voice.png`, `11-settings-github.png`,
  `19-column-config-exit.png`.

#### P1-5. Keyboard focus lands on destructive "Delete column" early
With Configure Column open, 10 Tabs from the board lands on the **Delete
column** button (the bright orange focus-ring at the bottom-left of the
dialog). A Space/Enter would open the delete confirmation. The dialog
appears to lack a focus trap that prioritises safe controls — the
destructive "Delete column" button is in the natural tab order ahead of
Cancel/Save.

- **Evidence:** test 22 reported `text: "Delete column"`,
  `outline: "5px auto rgba(233, 84, 32, 0.8)"` after 10 Tabs.
- **Fix:** move Delete out of the dialog tab order, or wrap with a
  `tabIndex={-1}` and surface a "Danger zone" expand-to-reveal pattern.
- **Screenshot:** `22-tab-focus-state.png` (Delete column ring visible
  bottom-left of the dialog)

### P2 — polish

#### P2-1. MCP tab tool list is hardcoded and stale
`src/components/settings/tabs/mcp-tab.tsx:56` says "19 Available Tools"
but `mcp-server/src/main.rs` exposes ~25 (per the count in
`CLAUDE.md > MCP Server` — read-only ×6, mutation ×11, workspace ×5,
template ×3 = 25). The visible list is missing at least:
`get_pipeline_template`, `list_pipeline_templates`,
`save_pipeline_template`, `apply_pipeline_template`,
`delete_pipeline_template`, `retry_from_start`.

- **Fix:** generate the list from a shared constant, or fetch it via an
  MCP introspection command at app start.
- **Screenshot:** `12-settings-mcp.png`

#### P2-2. Card "now" timestamp is visually loud
Every card on the board shows `now` in pale yellow at the bottom-right
corner (visible on all 7 seeded cards in `01-board.png` and
`02-card-hover.png`). The colour is the same accent yellow used for
warning badges, which competes with task-status icons (PR check, comment
count).

- **Fix:** demote relative timestamps to `text-text-tertiary` /
  `text-text-secondary` — it's metadata, not a status badge.
- **Screenshots:** `01-board.png`, `02-card-hover.png`

#### P2-3. Orchestrator collapse handle lacks affordance
The bottom-edge strip with `Chef` (left) and `Cmd+J to expand` (right) is
clickable but looks like a status footer — no chevron, no hover state in
the still. Users would not discover this as a panel without the keyboard
hint.

- **Fix:** add a visible chevron/handle icon and a hover background, e.g.
  reuse the resize-handle component pattern.
- **Screenshot:** `01-board.png` (very bottom edge)

#### P2-4. Settings content area wastes horizontal space on wide windows
At 1440px the Settings panel is `max-w-5xl` (~1280px) but the inner
content area is capped at `mx-auto max-w-3xl` (768px). Two-column
key-value rows (e.g. Board → Card Display toggles) have ~250px of dead
air on the right of every row.

- **Evidence:** `08-settings-board.png` — toggles end at x≈1410 inside a
  panel that extends to x=1440, but the label/control gap is enormous
  compared to a typical 600–700px form width.
- **Fix:** either remove `max-w-3xl` for full-width form rows, or use
  a two-column form grid so labels/controls align without empty middle.

#### P2-5. Column config tab triplet (General / Triggers / Exit) lacks tab semantics
The three text-only buttons at the top of the dialog use an
ad-hoc underline indicator for the active tab but no `role="tablist"`,
`role="tab"`, `aria-selected`, or `aria-controls` on the panels.

- **Fix:** convert to the standard tabs pattern (or use the shared
  Radix/headless tabs primitive if one already exists).
- **Screenshots:** `17-column-config-general.png`,
  `18-column-config-triggers.png`, `19-column-config-exit.png`

#### P2-6. Voice push-to-talk toggle visual state is hard to read
In `10-settings-voice.png` the "Push-to-talk" toggle is OFF — the orange
nub is barely visible against the bg-surface. Compare to "Enable voice
input" toggle in the same screenshot, which has a clearer off state.

- **Fix:** likely a shared toggle component — pick a single off-state
  colour with sufficient contrast.

#### P2-7. Settings @ 768px doesn't switch to the mobile section picker
The mobile select dropdown (`sm:hidden`) uses Tailwind's default `sm`
breakpoint (640px), so 641–767px gets the desktop sidebar inside a
`sm:max-w-2xl` (672px) panel — the sidebar then eats ~33% of the visible
panel width and the underlying column-config modal peeks through behind
the overlay (visible in `21-settings-narrow-768.png`).

- **Fix:** widen the mobile picker breakpoint to `md:hidden` and the
  sidebar to `md:block`, or set the settings panel to full-width below
  `lg`.
- **Screenshot:** `21-settings-narrow-768.png`

## Spec-infrastructure quirks documented for future audits

1. **WebKitGTK system titlebar steals 32px** above the React window. Any
   button at `y < 32` (the budget pill is at y=4, Settings cog at y=4)
   is unclickable via native WebDriver click — use `el.click()` in a
   `browser.execute` instead. See the `jsClick`/`jsClickByText` helpers
   in `audit-2026-05-13.spec.mjs`.
2. **`browser.keys(['Escape'])`** does not reliably deliver Escape to
   WebKitGTK pages — the column-config dialog has a working Escape
   handler (`column-config-dialog.tsx:149-156`) but stayed open in
   tests 20/22 despite the Escape send. Not a UI bug; reproduce manually
   if uncertain.
3. **Data dir pollution** between runs causes click-intercepted and
   screenshot timeouts. Always
   `rm -rf /tmp/kaitencode-wdio && mkdir -p /tmp/kaitencode-wdio` before each
   run, even though `KAITENCODE_DATA_DIR` is set.
4. **XPath `//button[normalize-space(text())="X"]`** does *not* match
   buttons whose label is wrapped in a `<span>` (e.g. settings tabs).
   Use `//button[.//span[normalize-space(.)="X"]]` or the
   `jsClickByText` helper.
