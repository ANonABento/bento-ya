### P0-2. Cmd+W permanently deletes the active workspace, no confirmation

**Where:** `src/components/layout/use-tab-bar-navigation.ts:39-43`, `65-69`.

```ts
const closeCurrentTab = useCallback(() => {
  if (activeWorkspaceId && sortedWorkspaces.length > 1) {
    void remove(activeWorkspaceId)            // <-- destructive: deletes DB row
  }
}, [activeWorkspaceId, sortedWorkspaces.length, remove])

// Cmd+W binding:
if (e.key === 'w') { e.preventDefault(); closeCurrentTab(); return }
```

`workspace-store.ts:58 remove()` calls `ipc.deleteWorkspace(id)`, which deletes the
workspace row and (per migrations) cascades to columns and tasks.

The same workspace deletion via Settings → Workspace → Danger Zone requires an explicit
"Are you sure?" dialog (`workspace-tab.tsx:333-356`). The keyboard shortcut bypasses it
entirely.

**Repro:**
1. Open Bentoya, open at least 2 workspaces.
2. Press Cmd+W (muscle memory from every browser/IDE/editor).
3. The active workspace and **all its tasks, columns, branches, worktrees, transcripts**
   are gone with no undo.

**Fix:** Either
- show the same confirmation dialog the Settings → Danger Zone uses, or
- make Cmd+W *hide* the tab (soft close) and require Settings for hard delete, or
- at minimum require Cmd+Shift+W for the destructive variant.

The shortcuts modal still advertises Cmd+W as "Close current workspace"
(`shortcuts-modal.tsx:34`), which suggests a soft close. Behaviour and label disagree.

### P0-4. No global Escape close for Settings, TaskSettings, Checklist, Onboarding

**Where:**
- `src/components/settings/settings-panel.tsx` — no `Escape` handler;
  `closeSettings` is fired only by backdrop click (line 141) and the explicit X button.
- `src/components/kanban/task-settings-modal.tsx` — no `Escape` handler.
- `src/components/checklist/checklist-panel.tsx` — no `Escape` handler.
- `src/components/onboarding/onboarding-wizard.tsx` — no `Escape` handler.

Compare to the modals that do handle it correctly:
- `command-palette.tsx:249`
- `shortcuts-modal.tsx:98-107`
- `column-config-dialog.tsx:136-142`
- `task-context-menu.tsx:220-222`

The shortcuts modal explicitly advertises `Esc → Close modal, panel, menu, or expanded
task` (`shortcuts-modal.tsx:26`). Half the modals violate it.

**Repro:** Open Settings (gear icon). Press Esc. Nothing happens. Same for any of the
other three.

**Fix:** Each modal adds:
```ts
useEffect(() => {
  const h = (e: KeyboardEvent) => { if (e.key === 'Escape') onClose() }
  window.addEventListener('keydown', h)
  return () => window.removeEventListener('keydown', h)
}, [onClose])
```
Or extract a shared `useModalEscape(onClose)` and apply it everywhere.

### P0-5. Workspace tabs cannot be closed from the tab bar

**Where:** `src/components/layout/tab-bar.tsx:50, 333-345`.

### P1-5. Multi-select multi-key gestures undocumented

- `src/components/layout/board.tsx:143-167` — Shift+click = range select, Cmd/Ctrl+click
  = toggle, plain click = single select.
- `task-card.tsx:407-411` — Cmd/Ctrl+pointer-down on card = start dependency drag.
- `task-card.tsx:181-189` — Cmd/Ctrl+click forwards to selection handler.

So on macOS, Cmd-click does both multi-select **and** dep-drag depending on which
handler wins. The dep-drag handler is `onPointerDownCapture` (capture phase) and
selection is on `onClick` — so dep-drag wins if you actually move the mouse, and
selection wins if you don't. Real-world result: users will sometimes start a
dep-drag when they meant to multi-select.

None of this is in `shortcuts-modal.tsx`. The user has to read source to know
multi-select exists.

**Fix:** Add to the shortcuts modal:
- `Shift + Click` — Range-select tasks
- `Cmd + Click` (without drag) — Toggle task in selection
- `Cmd + Drag from card` — Link task as dependency

Also consider distinguishing the two — e.g. require **Alt** for dep-drag, since Cmd is
already over-loaded with selection.

### P1-6. Task quick-action delete confirmation has no visible "Delete" trigger

`task-quick-actions.tsx:94-102` renders a "Confirm" button only when
`confirmDeletePending` is true. `confirmDeletePending` is set only by the keyboard
`Delete`/`Backspace` handler in `task-card.tsx:374-376`. There is no Delete button in
the always-visible quick-actions UI — the trash icon lives in the context menu (right-
click), and the "Confirm" button only appears post-keyboard-Delete.

**Repro:** Without using the keyboard, a user trying to delete via the hover quick
actions sees Open / Run / Move next / More — there is no trash. The "More" menu
contains Delete, which has no confirmation. So:
- Keyboard delete is two-step confirmed.
- Context-menu delete is single-step unconfirmed.

**Fix:** Make the two paths consistent. Either show Confirm on the context-menu Delete,
or wire `handleDeleteWithConfirm` from there too.

### P1-7. CLI session restart-on-model-switch dropped without notice

Per CLAUDE.md "CLI Session Model Changes": switching models mid-conversation forces a
new CLI session because Claude CLI ignores `--model` on `--resume`. The implementation
in `use-chat-session.ts` drops the resume ID and rebuilds a context preamble.

The user sees no indication — they pick a new model, hit Send, and the next agent
"forgets" any non-preamble context. There is no UI banner saying "switching models
restarted the agent." A user will assume context is intact.

**Fix:** When the chat hook detects a model-switch-induced session reset, post a tiny
inline transcript event ("Switched to opus — agent restarted with summary context")
before the next assistant reply.

### P1-8. Stop / Hold / Kill triple in agent panel is opaque

`agent-panel.tsx:159-203` shows three destructive-ish buttons:
- **Hold** — toggles `task.heldByUser` (auto-advance hold, not agent stop)
- **Stop** — sends Ctrl+C to the tmux session
- **Kill** — destroys the tmux session entirely (window.confirm dialog)

The button titles include hover text, but:
- The visible label "Hold" doesn't suggest "auto-advance"; it sounds like "pause agent".
- "Stop" vs "Kill" distinction (signal interrupt vs session destroy) is invisible
  unless the user mouses over.
- Kill is `border-error/30 bg-surface` styling — same color hue as Stop. They look
  near-identical at a glance.

**Repro:** A user wants to halt a runaway agent. They click Stop. The agent keeps
spinning (because it ignored Ctrl+C). They click Kill, which they expect is a
stronger Stop. The terminal scrollback vanishes — surprising side effect.

**Fix:**
- Reword **Hold** → "Pause queue" or move it under a "..." submenu.
- Re-style **Kill** as red destructive, not a sibling of Stop.
- The confirm dialog for Kill is `window.confirm` (line 95) — replace with a
  styled modal so it matches the rest of the app.

### P1-9. ResizeHandle min/max only applies via store, drag UX has no visual feedback

`use-resizable-panel.ts:50-55` computes `dragStartSize.current + delta` and calls
`onResize` with no local clamping. The clamp happens in
`ui-store.ts:174-178 setAgentPanelWidth` (300 ≤ width ≤ min(900, viewport-400)).

Consequences:
- On a narrow window (say 700px viewport), `getMaxAgentPanelWidth` returns 300, so the
  panel is locked at exactly 300. The resize handle still acts draggable but does
  nothing — confusing.
- Drag past the limits has no rubber-band, snap, or cursor change indicating you've hit
  a stop.

**Fix:** Disable the resize handle (cursor: not-allowed) and skip drag listeners when
the panel is at its clamped extreme. Or render a tiny "min width reached" hint.

### P1-10. Agent panel header truncation hides the working directory at narrow widths

`agent-panel.tsx:134-139`:
```tsx
<div className="truncate text-xs font-medium text-text-primary">{task.title}</div>
<div className="mt-0.5 flex items-center gap-1.5 text-[10px] text-text-secondary">
```

### P1-11. Settings panel `w-48` (192px) sidebar can't reflow on narrow

`settings-panel.tsx:169` — `<nav className="w-48 shrink-0 …">`. The panel itself is

### P1-12. ACTION_TYPES row uses `flex-1` across 7 buttons in a 576px modal

`column-trigger-action-editors.tsx:43-61` — 7 action types rendered as `flex-1`

"Move Column", "Create PR", "Auto Merge" don't fit on one line.

**Fix:** Switch to a wrapping grid (`grid grid-cols-3 gap-2`) so each button has at
least 150px and a coherent label.

## P2 — Polish / a11y / discoverability

### P2-1. Tailwind cursor classes used widely; known broken on macOS WKWebView

`AGENTS.md` and `CLAUDE.md` both call out that `cursor-pointer`, `cursor-grab`, etc.
don't render on macOS Tauri webview. The fix per project docs is inline `style={{ cursor: 'pointer' }}`.

Search showed 30+ remaining occurrences. Highlights:

- `column.tsx:218` — `cursor-grab active:cursor-grabbing` (column drag handle — visible affordance is broken)
- `column-header.tsx:215` — `cursor-default select-none`
- `task-context-menu.tsx:135` — `cursor-not-allowed`
- `task-card-status.tsx:128` — `cursor-pointer`
- `task-dependencies-tab.tsx:215` — `disabled:cursor-not-allowed`
- `orchestrator-panel.tsx:298, 307, 320, 334, 348, 378, 395, 413` — heavy use across the chef panel header
- `panel-sidebar.tsx:180` — `disabled:cursor-not-allowed`
- `panel-input.tsx:228, 262` — `disabled:cursor-not-allowed`
- `tab-bar.tsx:81` — `cursor-pointer`
- `path-picker.tsx`, every `Button` and `IconButton` consumer (transitively)
- `dropdown.tsx:73`, `select.tsx:21`, `toggle.tsx:24`, `icon-button.tsx:44`,
  `setting-components.tsx:82, 115, 146, 298` — shared atoms

Many of these are user-visible: dragging a column is the most "active" affordance on
the board and the grab cursor isn't showing up on macOS.

**Fix:** Either switch the offending sites to inline styles, or add a global CSS rule
that targets these utility class names with `!important` to work around WKWebView's
behavior, or move to a small `<DraggableHandle>` shared component that applies inline
cursor inside.

### P2-2. Task cards have no a11y role / aria-label

`task-card.tsx:325-414` — the card is a `<div>` with `tabIndex={0}` and elaborate
`onKeyDown` handling, but no `role="button"` (or `role="article"`), no `aria-label`
synthesizing the title and state, no `aria-pressed` for selection, no
`aria-describedby` for the status banners that appear/disappear.

Result: a screen-reader user navigating with Tab hears "" or the raw concatenated
text of the rendered content with no semantic structure.

**Fix:** Add `role="button"`, `aria-pressed={isSelected}`, `aria-label={task.title}`
and `aria-describedby` for the banners. The card-as-button + nested-buttons pattern is
slightly unusual; consider `role="group"` with explicit inner buttons.

### P2-3. Settings tabs list in command palette is hardcoded

`command-palette.tsx:172-180` — duplicates the tab list inline. Out of sync with
`settings-panel.tsx:72-83`. (Same root cause as P1-1.)

**Fix:** Export `SETTINGS_TABS` from a constant and import in both places.

### P2-4. Cmd+T (new workspace), Cmd+W (close), Ctrl+Tab — all conflict with native

These shortcuts are listed in `shortcuts-modal.tsx:32-37`. On macOS, Cmd+T is "new
tab" in the system menu and Cmd+W is "close window". Tauri 2 binds menu shortcuts
automatically. Whichever wins depends on focus state and the menu config. Users coming
from VS Code will hit Cmd+W expecting to close a side panel and end up in the workspace
deletion path (P0-2).

**Fix:** Choose less-overloaded combos (Cmd+Shift+T, Cmd+Shift+W) or remove the
binding entirely and rely on the gear icon.

### P2-5. Confirmation patterns inconsistent across destructive actions

| Action | Confirmation pattern |
|---|---|
| Column delete (has tasks) | Styled modal `column.tsx:316-348` |
| Column delete (empty) | None — just calls `remove()` |
| Task delete (keyboard) | 2-click confirm with 2s timeout `task-card.tsx:265-280` |
| Task delete (context menu) | None — single click destroys |
| Bulk task delete | `window.confirm()` `board.tsx:185` |
| Workspace delete (Settings) | Styled modal `workspace-tab.tsx:333-356` |
| Workspace delete (Cmd+W) | None |
| Kill tmux session | `window.confirm()` `agent-panel.tsx:95` |
| Run-all queue | Styled modal `column-header.tsx:326-358` |

Three flavours of confirmation (styled modal / window.confirm / 2-click / none) for
semantically similar operations. Users learn nothing transferable.

**Fix:** Standardize on a styled `<ConfirmDialog>` for all destructive actions, or at
least all that touch >1 row.

### P2-6. Quick actions are hover-only — touch and trackpad-tap users lose them

`task-quick-actions.tsx:32` — `opacity-0 group-hover:opacity-100`. Behind a finger or
on a trackpad without sustained hover, these are invisible. Keyboard nav exposes them
indirectly (Space = run agent, → = move next, etc.) but only if you know the cards
respond to tab focus.

**Fix:** On focus-within, also reveal quick actions (`group-focus-within:opacity-100`).

### P2-9. Onboarding wizard's "Browse" button can't be tested in dev/mock mode

`path-picker.tsx:15-24` calls `open()` from `@tauri-apps/plugin-dialog`. In Vite dev /
Playwright (without Tauri), `open` throws and is caught silently. So:
- Browser mock cannot complete onboarding via Browse.
- The text input fallback works, but users dropped into the demo might expect Browse to
  do something visible.

**Fix:** In `__mocks__/`, stub `open` to return a synthetic path (e.g.
`/tmp/demo-repo`). Or render an error toast when Browse fails in non-Tauri mode.

### P2-10. Command palette "Create new task" silently uses search text as title

`command-palette.tsx:108-119`:

### P2-11. Path picker rejects nothing — empty / non-existent paths accepted
