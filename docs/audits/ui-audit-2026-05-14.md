## P1 — Fix soon

### P1-1. Hover quick-actions overlay intercepts clicks even when invisible

**Where:** `src/components/kanban/task-quick-actions.tsx:31-34`

```tsx
return (
  <div
    className="absolute right-1 top-1 flex items-center gap-0.5 opacity-0 group-hover:opacity-100 transition-opacity z-10"
    onClick={(e) => { e.stopPropagation(); }}
  >
```

**Repro:** WDIO reported 4 failing tests with `element click intercepted` on task cards. The hover overlay uses `opacity-0` but no `pointer-events-none`, so the absolute `z-10` div still hit-tests at opacity 0. When WebDriver computes the click point and it falls inside the overlay region, the overlay's `onClick={e.stopPropagation()}` swallows the click intended for the article. Users who land their cursor on the top-right of a card before its content can also briefly fail to click through.

**Fix:** Add `pointer-events-none group-hover:pointer-events-auto` to the overlay className. Keeps the fade-in animation; disables hit-testing when invisible.

```tsx
className="absolute right-1 top-1 flex items-center gap-0.5 opacity-0 pointer-events-none group-hover:opacity-100 group-hover:pointer-events-auto transition-opacity z-10"
```

One-line change, unblocks WDIO regression coverage for transcript/terminal panes.

### P1-5. Settings drawer has no focus trap — Tab leaks into background board

**Where:** `src/components/settings/settings-panel.tsx:208-310`

**Repro:** Open Settings and press Tab repeatedly. Focus eventually leaves the drawer and lands on background board buttons (Add task / Run All) sitting behind the dimmed backdrop. Drawer never auto-focuses an initial element on open.

**Fix:** Hand-rolled focus trap (no new dep):

```tsx
const closeBtnRef = useRef<HTMLButtonElement>(null)
const panelRef = useRef<HTMLDivElement>(null)

useEffect(() => {
  if (isOpen) {
    requestAnimationFrame(() => closeBtnRef.current?.focus())
  }
}, [isOpen])

function onPanelKeyDown(e: React.KeyboardEvent) {
  if (e.key !== 'Tab') return
  const focusables = panelRef.current?.querySelectorAll<HTMLElement>(
    'button, a, input, select, textarea, [tabindex]:not([tabindex="-1"])'
  )
  if (!focusables || focusables.length === 0) return
  const first = focusables[0]
  const last = focusables[focusables.length - 1]
  if (e.shiftKey && document.activeElement === first) {
    e.preventDefault(); last.focus()
  } else if (!e.shiftKey && document.activeElement === last) {
    e.preventDefault(); first.focus()
  }
}

<motion.div ref={panelRef} onKeyDown={onPanelKeyDown} …>
  <button ref={closeBtnRef} onClick={closeSettings} …>×</button>
```

### P2-5. Column color radiogroup is not arrow-navigable

**Where:** `src/components/kanban/column-config-dialog.tsx:386-401`

**Repro:** Tab through the radiogroup — each of the ~10 color swatches is its own tab stop. ARIA Authoring Practices require roving tabindex + arrow-key cycling for radiogroups.

**Fix:** Roving tabindex pattern:

```tsx
const entries = Object.entries(COLUMN_COLORS)
const currentIdx = entries.findIndex(([, c]) => c === color)
function onKeyDown(e: React.KeyboardEvent, idx: number) {
  if (!['ArrowLeft','ArrowRight','ArrowUp','ArrowDown'].includes(e.key)) return
  e.preventDefault()
  const delta = e.key === 'ArrowLeft' || e.key === 'ArrowUp' ? -1 : 1
  const next = (idx + delta + entries.length) % entries.length
  setColor(entries[next][1])
  ;(e.currentTarget.parentElement?.children[next] as HTMLElement)?.focus()
}
…
<button
  …
  tabIndex={color === c ? 0 : -1}
  onKeyDown={(e) => onKeyDown(e, idx)}
/>
```
